# Governance and development process

This file describes how the WaggleDance repository itself is developed and reviewed. It is not needed to run or use the software. The binding rules live in [`CLAUDE.md`](CLAUDE.md) and in the documents linked below; this page only collects them in one place and explains the vocabulary. It does not change any rule or any licence term.

## Development agent bridge

This repository is developed by a fleet of agents that coordinate through an append-only bridge event log (`.agent-bridge/`): Codex Lead and Tools lanes, Claude review (RCO1, RCO2) and implementation (Fable) lanes, and an advisory Grok lane. Every change lands through a pull request, and the merge gate decides which review route applies. The gate's default (legacy) route needs, among other conditions, Lead and Tools build votes, an independent RCO pass bound to the exact head, green required CI, no unretracted RCO veto, and an explicit operator signature for off-allowlist changes ([`CLAUDE.md`](CLAUDE.md), Rule 9a). When the Rule 12 review policy is selected, best-available consensus applies instead: one approval from the model family opposite to the implementer, an RCO pass from two distinct recognized RCOs when at least two are eligible, otherwise from the one that is (a Grok fallback for the RCO slot only when none is eligible or present; in the gate as implemented that fallback is an opt-in switch, default off, and any other Grok fill is report-only), green required CI, no unretracted veto or finding from any recognized RCO, the charter checks, and a MAGMA receipt naming every slot holder ([`CLAUDE.md`](CLAUDE.md), Rule 12).

After a reboot the operator restores the fleet from the installed reboot bundle with `start-wd-all.ps1 -Auto` ([`ops/windows/reboot/BOOT_AFTER_REBOOT.md`](ops/windows/reboot/BOOT_AFTER_REBOOT.md)). Bridge changes are recorded in [`CHANGELOG.md`](CHANGELOG.md); the last bridge release tag is `bridge-2026.09.27-bridge-final-acceptance`.
