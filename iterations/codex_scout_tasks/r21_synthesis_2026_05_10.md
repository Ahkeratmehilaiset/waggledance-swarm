## R21.1 measurement plan (concrete, ratified)

Per Claude Part 1 §"Quality metric formula":

```
quality_arm = (
    correct_positive_routings / total_positive_utterances
    + correct_negative_rejections / total_negative_utterances
) / 2
```

Where:

- correct_positive_routing: `select_origin_cell(positive_utterance)`
  returns the `cell` named in the oracle file
- correct_negative_rejection: `select_origin_cell(negative_utterance)`
  does NOT return that same cell (because the negative utterance is
  for a *different* solver/domain)

Aggregation: **macro-average across oracle files** (recommended;
prevents large oracles from drowning out small ones; final operator
call surfaced below).

Cache discipline (operational risk #2 from Claude Part 1): both A/B
arms share the same warm cache OR both run with cache disabled.
Default is cache disabled for the run; `BridgeLLMClient` factory
constructor for the harness uses `providers=[OllamaProvider(),
HeuristicProvider()]` (no `ExactCacheProvider`) so neither arm gets
a cache advantage.

## R21.1 expected-result honesty (from Claude Part 1)

**The control heuristic may already be near ceiling on this corpus.**
Post-#171 substring-match against pre-lowercased selectors with
agent-count tiebreak likely correctly routes 85–95% of positive
utterances (those utterances were authored to exercise specific
cells). At that ceiling, 20% gain (≥1.02) is mathematically
impossible; the realistic LLM head-room is 5–15 percentage points.

**This is not a reason to skip R21.1.** Per R20 rule 17 + Decision
B + R21.5 gate (1):

- A measured `delta_quality < 20%` → keep treatment **disabled**, log
  the result honestly.
- The result still satisfies R21.5 gate (1) ("R21.1 has a real
  `delta_quality` number"). Axis B in `EVOLUTION_INDEX.md` becomes
  non-`null` for the first round in the project's history.
- Honest logging > manufactured win. The synthesis MUST NOT pressure
  the R21.1 implementer to game the metric to claim ≥20%.

   Should `quality_arm` weight them equally (current formula above) or
   weight by absolute count? Synthesis recommends equal weight (the
   formula already does this) — it removes the "easy win on positives,
   ignore negatives" failure mode.
