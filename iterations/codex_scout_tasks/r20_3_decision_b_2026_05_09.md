keep the augmentation behind a flag; otherwise document as Decision B.

## Why no production wire-up landed in this PR

R20 master prompt §2.4 requires every augmentation point to be
"tested first in A/B mode" with "1000+ calls if feasible" and a
quality score `delta_quality` measured against an oracle.

**There is no labelled corpus**:

- `case_trajectory.quality_grade` would need a held-out set of cases
  with operator-marked ground-truth grades. None exists today.
- `select_origin_cell` has the bench fixture's 6 query samples
  (`bee hive swarm weather safety` → `bee_ops`, etc.) but those are
  routing-decision parity samples, not preference-graded labels.
- The synthesis explicitly noted `axis_b_quality: null` until R20.3
  introduces a quality oracle; without that oracle, the 20% gain
  threshold cannot be evaluated.

Per R20 master prompt rule 6 ("Do not weaken bridge, orchestrator,
claim, or token hygiene"), shipping a hot-path LLM call without the
quality measurement that gates its retention would be premature: it
turns into a "maybe useful later" augmentation, which rule §2.4
explicitly forbids. Rule 17 says "remove it or leave it disabled with
clear evidence" if the threshold isn't met — so the safe path is to
ship the **substrate** (BridgeLLMClient + ABHarness) and document the
exact criteria that activate the wire-up.

## What this PR DOES ship

- `waggledance/core/bridge_llm/ab_harness.py` — `ABHarness` class with
  `treatment_share` parameter (default 0.0 — treatment never runs).
  When `share > 0` and a `treatment_request` is supplied, both arms
  are computed and the production decision is selected by share.
  Treatment failures fall through to control without crashing the
  call. Records `latency_control_ms` + `latency_treatment_ms` per
  decision so operators can see treatment cost. Profile S
  compatibility: when `BridgeLLMClient.disabled()` is used (Profile S
  default), the treatment arm short-circuits to the heuristic
  provider — no LLM SDK is imported.
- `tests/test_bridge_llm_ab_harness.py` — 7 cases:
  - share=0 skips treatment entirely
  - share=1 runs both arms and treatment is chosen
  - treatment exception falls through to control without crashing
  - latencies recorded for both arms
  - invalid share raises
  - missing treatment_request skips the treatment arm
  - share=0.5 over 100 samples routes proportionally (40-60 band)

The harness is the missing **plumbing**; the wiring of any specific
injection point is now a one-PR follow-up once an oracle exists.

## Activation criteria (the conditions that close R20.3 fully)

When operator brings any of:

- a labelled corpus of (case_trajectory_input, ground_truth_grade)
  pairs with ≥100 examples, OR
- a deterministic golden-output evaluator for a single decision
  (e.g. routing should produce cell X for query Y), OR
- an operator review channel that can grade ≥10 decisions/day for a
  week,

then a follow-up PR will:

1. Pick the matching injection point (case_trajectory if labelled
   grades; select_origin_cell if golden routes; bridge severity if
   operator review).
2. Wire `ABHarness` into that call site via the existing module-
   global `BridgeLLMClient.default()` (already available).
3. Run the A/B with `treatment_share=0.5` over the available sample
   size.
4. Compute `delta_quality = (quality_treatment - quality_control)
   / quality_control * 100`.
5. If `delta_quality >= 20`: keep the treatment behind config flag
   `WAGGLE_R20_3_AB_<INJECTION_POINT>_ENABLED` and update
   EVOLUTION_INDEX.md `axis_b_quality` for the round.
6. If `delta_quality < 20`: remove or keep disabled per rule 17.

This is the literal spec — no operator decision required, just the
oracle.

## Why this is honest

The R20 master prompt rule 4 explicitly accepts "explicit 'no
measurable improvement, abandoned' result" — this is the same
pattern as R18 Cand 2 (deliver_batch relation index). That precedent:
ship the architectural primitive when correctness is provable but
measurement isn't yet feasible at the workload size, document
exactly what would change the result, do not pretend the
measurement happened.

This is the same shape: BridgeLLMClient.disabled() works; ABHarness
share=0.0 default never runs treatment; the substrate is real; the
quality measurement is what's missing.
