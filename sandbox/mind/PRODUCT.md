## What a lane gets

One card per turn, at most 2048 bytes, in fixed line order. One command, `join_turn.py`, turns one verified frozen
capture cycle into one lane's card. The lines carry their refs (PR heads, vote refs, the delivery identity, lesson
refs), and an unsure fact is `UNKNOWN` with a reason, never a guess. REMEMBER lines appear only when the turn supplies
a REMEMBER answer bound to this lane and this view's as_of; otherwise there is no REMEMBER line. LEARN notes and
lesson warnings (card v0.5) appear only when the turn supplies a LEARN v1 state that matches its own hash and this
LEARN's parameters; otherwise the LEARN line says that the card records nothing. This is an example rendered from
the synthetic test fixtures (card v0.5, with LEARN notes):

## Known limits (they stay in every card and in the landing description)

* REMEMBER is a smoke pass, not proven. n is 16 positives and 6 negatives, the joiner was from the author's model
  family (cross-family usefulness is UNKNOWN), the two graders labelled differently (read-based and mechanical), and
  all three sealed sets are now used. Any v2.1 needs a new pre-registration and new blind cases.
* REMEMBER arm (card v0.4, 2026-10-18 sandbox, unreleased): the turn runner must declare the arm in the envelope,
  and the card renders only the joined arms v2a and v2ca, with the arm in the citation; a v2c or unknown arm is
  refused. The declaration is checked, not verified: the card cannot see which code produced an answer (REMEMBER v2
  puts the same version in every arm), so a runner that labels a v2c answer as v2ca still renders it, as with
  `situation_sha256`.
* On fresh, independently worded pairs the true lesson is present, but its opposite is unmarked in 80/80 v2a
  observations (RCO1).
* A forged-date flood hides the true lesson in 8/20 of the old A/B v2a shortlists (a probe run after the code was
  written). Ordering trusts writer-chosen dates; verified availability is not considered yet.
* v2c (code only, no joiner) is NOT YET (10/16; negatives 4/6), and with an identity rewrite a flood hides the true
  lesson in 13/20 fresh answers. A card must never show a v2c result as an answer.
* Privacy: the shortlist guard was not independently exercised, because RCO1's guarded fixtures were rejected at
  corpus build. RCO1's injection probe of the JOIN path at adb8949f (result 345f8464; one run, 658 injections into
  the string leaves of the answer, the view and the receipts; peer evidence from a disclosed card-frame contributor):
  no documented variant (case, escapes, fullwidth, either word) leaked or wrote a turn; each was refused at delivery,
  render or write_turn with nothing written, or left the output clean. Forms outside its decoding claim passed it
  and could reach the turn files: an HTML entity, percent encoding, ZWJ or ZWNJ inside a word, and a Cyrillic
  look-alike letter; a soft hyphen was refused where it is rendered but reached view.json from a field that is not
  rendered. The 2026-10-18 sandbox patch (fable-5, unreleased) widens the shared guard (`_has_marker` in
  `tools/bridge_mind_workspace.py`): it also decodes HTML character references and percent encoding, in any order
  and mix with backslash-u, and adds each form's skeleton to the decoded forms: the compatibility decomposition
  with format characters (Cf) and every combining mark (Mn, Mc, Me) removed and Cyrillic or Greek look-alike letters
  read as Latin. So a decoding behind a fullwidth percent sign or ampersand, or a zero-width character inside an
  escape, is decoded too (Lead's review of the first patch found those two gaps, F1 and F2). Unit tests cover each
  of those forms and 13 named mutants are killed; RCO1's injection probe was NOT re-run. A text that still yields
  new forms after 3 decodings or past 64
  forms is refused (an accepted over-refusal). Still outside the claim: look-alikes outside the mapped letters,
  other invisible letters (such as a Hangul filler), other encodings (base64, MIME, punycode), a word split by a
  space or punctuation, and the separate copy of the old guard in `tools/wd_bridge_mind_delta_push.py`. There is
  no blanket privacy pass.
* REMEMBER binding (card v0.1): the card checks the lane, the turn (as_of) and the answer digest. The digest is
  self-consistency, not origin. `situation_sha256` is cited, not verified: an answer made for another situation at
  the same lane and as_of renders with only the citation changed (RCO2 P4, measured).
* Card text (v0.3): the check is on the card's own code points, and the card's presentation contract is plain text:
  no rendered view is certified (Lead triage 7126b428). Shown as Markdown outside a code block, a renderer may join
  the card's lines into one paragraph, where the bidi algorithm can reorder text across them, and may decode raw HTML
  or character references in a field; what a given renderer does is UNKNOWN (none was tested), so show the card as
  plain text or in a code block. Refusing format characters (Cf) follows Grok 1035d2a9's advice and is a policy
  choice, not a measured acceptance. REMEMBER v2 removes only whitespace, so genuine REMEMBER text that holds a
  control or format character refuses the whole card; how often that happens was not measured. Invisible characters
  outside these categories still render, because genuine text needs them: ZWJ and ZWNJ, variation selectors, the
  combining grapheme joiner and Hangul fillers. They can still carry hidden data, such as bytes encoded in variation
  selectors. The rule follows this interpreter's Unicode data (15.1.0): a code point unassigned there renders even if
  a later Unicode version makes it a format character.
* JOIN turn: since v0.1 (572f41b0) the four files are written into a fresh sibling staging directory and one rename
  moves the whole turn into place, so the output directory holds the complete turn or does not exist. A crash can
  leave a `.<name>.staging-<16 hex>` directory beside it; it is never a turn, and nothing removes it automatically.
  This is a tested design property (injected crashes and errors), not a whole-directory or crash-safety claim: no
  power-loss test was run, and no directory is flushed, so a successful return does not make the rename durable. An
  existing output directory is refused; on POSIX, rename(2) could still replace a directory that another writer
  created empty during the call (the sandbox runs on Windows, where an existing directory refuses the rename,
  measured). A frozen cycle is never live input, and `now` defaults to the cycle's as_of, never the wall clock. Since
  6d47c453 a file nested too deeply to read, or to write as an output, is refused with the fixed reason before any
  byte is written. Missing parents of the output directory are created first and stay, also after a refusal. Since
  v0.2 the staging directory must hold exactly the four files just before the rename: a file that another writer puts
  there is refused, not carried into the turn, and only a file that appears between that check and the rename would
  still be carried. The cleanup after a refusal or an error is best effort: each step tolerates any ordinary
  exception, a staging directory that cannot be removed stays (even empty), and the caller still gets the original
