# ADR-062 — AI-Assisted Bootstrap Kit

* Status: **substrate-only landing** (contract + ADR pinned; implementation deferred)
* Date: 2026-05-12
* Related: ADR-031 (confidence-bin gap mining), ADR-034 (anti-cargo-cult), ADR-038 (tunnel overlay), ADR-050 (domain bridging), ADR-055 (profile-aware budgets)
* Strategic: differentiates WaggleDance from peer multi-agent frameworks by integrating world-class AI reasoning models (Claude Opus, OpenAI Codex) directly into the bootstrap learning loop

## Context

Today's fresh deployment (any profile: GADGET / COTTAGE / HOME / FACTORY) starts with **zero domain content**:

* No starter solvers — autogrowth_scheduler mines candidates from runtime gap signals, which only exist AFTER queries flow.
* No anti-feature library (L25) — failure-pattern mining only has data after rejections accumulate.
* No anti-cargo-cult probes (L29) — operator must hand-curate the probe YAML.
* No tunnel overlay seed (L2 + L5) — co-fire mining (L3) needs weeks of telemetry to find useful tunnels.
* No training distribution hints — confidence-bin gap mining (L21) must discover bin boundaries by trial.

The system therefore needs **weeks of real query traffic** before it starts behaving as a useful WaggleDance deployment. Meanwhile, two of the most capable reasoning models on Earth (Claude Opus 4.7, OpenAI Codex) sit IDLE between sessions, holding latent knowledge about:

* What apiary / home / factory solvers SHOULD look like
* What known anti-patterns to avoid
* What adversarial inputs the system MUST handle correctly
* What plausible cross-domain tunnels to seed
* What confidence-bin distributions are realistic for each domain

**Strategic gap**: WaggleDance does NOT yet harness AI reasoning models as a BOOTSTRAP source. Peer frameworks (Aider, Cline, AutoGen, CrewAI) use AI for inference at runtime — none use AI to seed the agent fleet's startup state.

This ADR closes that gap by pinning the **AI-Assisted Bootstrap Kit** mechanism: a profile-specific YAML kit, generated by external AI (Claude / Codex / future models), loaded ONCE on fresh deploy. The kit primes the autogrowth + trust + tunnel substrate so the deployment starts with non-trivial domain content from day 0.

## Decision

Profile-specific bootstrap kits live at:

```
configs/bootstrap_kit/{GADGET|COTTAGE|HOME|FACTORY}.yaml
```

Each kit is a YAML document with the following structure:

```yaml
schema_version: bootstrap-kit-v1
profile: GADGET | COTTAGE | HOME | FACTORY
provenance:
  ai_provider: claude_opus_4_7  | openai_codex | meta_consensus
  ai_version: "claude-opus-4-7-2026-05-12"
  generated_at_utc: "2026-05-12T12:00:00Z"
  training_data_summary: "session synthesis 2026-05-12 / 1049-obs corpus + bridge events / waggledance v3.12.0 substrate"
  signature_hash: "<sha256 of canonical kit bytes>"

starter_solvers:
  - capability_id: solve.math
    solver_id: starter_arithmetic_basic_v1
    spec: {...}    # full solver spec per existing solver schema
  - ...

anti_features_seed:
  - feature_name: "conditional_branches"
    threshold: ">2"
    rationale: "solvers with >2 conditional branches showed 80% rejection rate in training corpus"
  - ...

anti_cargo_cult_probes_seed:
  - probe_id: probe-fi-pii-leak-001
    input: "Asiakkaan henkilötunnus on 010101-123A"
    expected_class: "redact_pii"
    baseline_accuracy: 0.95
    added_at_utc: "..."
    added_by: "claude_opus_4_7@bootstrap"
  - ...

tunnel_overlay_seed:
  - tunnel_id: <uuid>
    from_cell: home_comfort
    to_solver: thermal_solver
    direction: forward
    trust_score: 0.75
    provenance_event_id: "bootstrap_kit_seed"
    rationale: "thermal queries frequently originate from home_comfort context in HOME profile"
  - ...

training_distribution_hints:
  confidence_bin_targets:
    deep: 0.20   # expect 20% deep-bin queries in this profile
    borderline: 0.30
    marginal: 0.30
    confident: 0.20
  domain_volumes:
    apiary: 0.40
    home: 0.35
    energy: 0.15
    general: 0.10

validation_results:
  anti_cargo_cult_pass_rate: 0.98
  hot_path_budget_compliance: true
  l51_contract_check: true
  signed_off_by: operator_id
  signed_off_at_utc: "..."
```

A new component, `BootstrapKitLoader`, runs at `Container.__init__` (per profile):

1. Detects fresh deploy by checking `control_plane.bootstrap_state` table (empty = fresh).
2. If fresh AND kit file exists for active profile: loads kit, validates signature_hash, applies to relevant adapter caches.
3. Logs kit provenance to events.jsonl for audit trail.
4. Marks `bootstrap_state.loaded_at_utc` so kit is loaded EXACTLY ONCE.

A separate `BootstrapKitGenerator` is operator-triggered (not autonomous):

1. Operator runs `python tools/generate_bootstrap_kit.py --profile=GADGET --ai-provider=claude_opus_4_7`.
2. Tool prompts the AI provider with a structured request (profile + training corpus reference).
3. AI returns a draft kit YAML.
4. Tool runs draft through validation pipeline:
   * ADR-034 anti-cargo-cult gate on the proposed probes themselves
   * ADR-034 anti-cargo-cult gate on the starter_solvers against the proposed probes
   * ADR-027 hot-path budget on starter_solvers (sample-test)
   * ADR-038 + ADR-040 trust-threshold check on tunnel_overlay_seed
   * L51 contract test on the kit schema itself
5. Validated kit gets `validation_results` block populated + `signature_hash` computed.
6. Operator signs (`signed_off_by`) before committing to repo.

## Strategic positioning

This is the **largest single capability gap** between WaggleDance and peer multi-agent frameworks. Filling it:

* **Differentiates** from Aider / Cline (code-only) and AutoGen / CrewAI (orchestration-only): WaggleDance becomes the first multi-agent framework with AI-curated bootstrap KITS, not just AI-driven inference.
* **Accelerates** deployment: fresh GADGET goes from "zero-knowledge" to "behaves like a 2-week-trained system" on day 0.
* **Auditable**: every kit has provenance + signature + operator sign-off. Not a black-box trust transfer.
* **Multi-AI consensus** future-proof: kits CAN be generated by Claude, by Codex, or as a CONSENSUS of multiple providers (with disagreement triggering operator review).

## Consequences

### Bootstrap experience

* GADGET fresh deploy: 50-150 starter solvers + 20 probes + 10 anti-features at boot. Useful day-0 behavior.
* COTTAGE: 150-300 starter solvers + 50 probes + 30 anti-features + 10 initial tunnels.
* HOME: 500-1000 + 200 + 80 + 30 tunnels.
* FACTORY: 2000+ + 500 + 200 + 100+ tunnels.

### Validation pipeline

* Every kit MUST pass ADR-034 + ADR-027 + ADR-038 gates before commit. No trust transfer without verification.
* Kit signature_hash prevents in-transit tampering.

### Operational

* Kits are version-controlled (one PR per kit update). Operator audits the diff.
* Kit generation is operator-triggered, not autonomous. Cron schedule (`quarterly_kit_refresh`) is operator-policy, not code-policy.
* AI providers used for generation are NOT used at runtime — kits are static YAML, no live AI dependency.

## Invariants

Pinned in `docs/eig2/contracts/ai_assisted_bootstrap_kit.json` and verified by `tests/contracts/test_ai_assisted_bootstrap_kit.py`.

1. **YAML path per profile**: kits at `configs/bootstrap_kit/{profile}.yaml` exactly.
2. **Schema-versioned**: `schema_version=bootstrap-kit-v1`. v2 bump requires ADR amendment.
3. **Provenance required**: ai_provider, ai_version, generated_at_utc, training_data_summary, signature_hash all required. NULL forbidden.
4. **Signature hash anchored**: signature_hash = sha256(canonical_json(kit minus signature_hash field)). Tampering detected.
5. **Load exactly once**: `bootstrap_state.loaded_at_utc` prevents re-load on subsequent boots. Idempotent.
6. **Validation pipeline mandatory**: kit MUST have non-empty validation_results block populated by `BootstrapKitGenerator`. Hand-edited kits without validation_results rejected at load.
7. **Operator signature required**: `signed_off_by` and `signed_off_at_utc` required. Unsigned kits rejected at load.
8. **No runtime AI dependency**: kit content is static YAML. Loader does NOT call AI providers at runtime — only at generation time (operator-triggered).
9. **Profile-locked**: kit's `profile` field MUST match Container's active profile. Cross-profile load attempts rejected.
10. **L51 schema gate**: kit YAML structure (top-level keys) is contract-tested against this ADR; future schema additions require contract-test amendment.

## Out of scope (this ADR)

* Implementation of `BootstrapKitLoader` + `BootstrapKitGenerator` — separate PR.
* The actual GADGET / COTTAGE / HOME / FACTORY kit content — generated separately by AI providers per operator request.
* Multi-AI consensus generation (Claude + Codex agree on a kit) — future ADR if pursued.
* Kit auto-update cron — operator-policy, not code.
* Bootstrap-kit MARKETPLACE (community-shared kits) — explicitly NOT planned for v3.x.
