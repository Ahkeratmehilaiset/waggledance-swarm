# v3.12.0 Torch Lock Evidence - 2026-05-22

Status: implementation evidence only. This is not final stable evidence and does
not mark `security_privacy_gate` pass.

## Decision

The operator decision pack `docs/operator_inbox/torch-cuda-vs-cpu.yaml` is
signed for `A2_cu126`: keep GPU support and move the torch family to CUDA 12.6.

This PR implements that lock direction in `requirements.lock.txt`:

- Adds `--extra-index-url https://download.pytorch.org/whl/cu126`.
- Moves Windows pins to `torch==2.11.0+cu126`,
  `torchvision==0.26.0+cu126`, and `torchaudio==2.11.0+cu126`.
- Moves non-Windows pins to matching plain PyTorch versions.
- Moves `torchao` to `0.17.0`.
- Keeps `xformers==0.0.35`, which is the current version exposed by the
  PyTorch cu126 index.

## Local Index Checks

Commands:

```text
python -m pip index versions torch --index-url https://download.pytorch.org/whl/cu126
python -m pip index versions torchvision --index-url https://download.pytorch.org/whl/cu126
python -m pip index versions torchaudio --index-url https://download.pytorch.org/whl/cu126
python -m pip index versions xformers --index-url https://download.pytorch.org/whl/cu126
python -m pip index versions torchao
```

Observed:

- `torch`: `2.11.0+cu126` is available.
- `torchvision`: `0.26.0+cu126` is available and resolver-compatible with
  `torch==2.11.0+cu126`.
- `torchaudio`: `2.11.0+cu126` is available.
- `xformers`: `0.0.35` is available on the PyTorch cu126 index.
- `torchao`: `0.17.0` is available on PyPI.

Rejected tuple:

```text
torch==2.11.0+cu126
torchvision==0.27.0+cu126
torchaudio==2.11.0+cu126
```

Resolver result:

```text

ResolutionImpossible
```

## Evidence Tool

New command:

```text
python tools/run_release_torch_lock_evidence.py \
  --operator-decision-pack docs/operator_inbox/torch-cuda-vs-cpu.yaml \
  --requirements-lock requirements.lock.txt \
  --output docs/runs/release_soak_evidence/v3.12.0_torch_lock_evidence.json
```

The tool checks the signed operator decision and the lock file together. It
fails closed if:

- the operator decision pack is unsigned or not `A2_cu126`,
- the PyTorch cu126 extra index is missing,
- Windows pins are not the expected `+cu126` pins,
- non-Windows pins do not match the plain PyTorch versions,
- stale `+cu118` or `2.7.1` torch-family pins remain,
- `torchao` is not at the compatibility pin,
- `xformers` is neither retained at the observed cu126-index version nor
  explicitly dropped in a separate de-scope PR.

The emitted JSON always keeps:

- `release_gate_effect = "none"`
- `security_privacy_gate_status = "unchanged"`
- `fresh_pip_audit_required = true`
- `pip_audit_skip_is_not_clean = true`

## Remaining Release Blocker

A fresh full dependency audit is still required before stable release. During
this session, a full `pip-audit -r requirements.lock.txt` run did not complete
within the timebox and earlier release evidence still reported non-torch
dependency blockers. This PR therefore implements the authorized torch lock
path but does not claim a clean dependency audit or a release gate pass.
