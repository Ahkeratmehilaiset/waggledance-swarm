# ADR: durable bridge continuity after a lane stops

Status: proposed, 2026-09-29. This document grants no deployment, merge, release, runtime, or HOLD-override authority.

## Observed failure and immediate slice

An expired claim can be archived while its `release/stale_lease` event has no `to` recipient. `Watch-Bridge.ps1` wakes addressed lanes; a release addressed to nobody cannot wake the former owner or its dispatcher. `Get-BridgeNextAction.ps1` can also prefer an active own claim over an older open request, so a pending request can remain unseen until the claim is released and the lane is woken again. A queue acceptance is not a completed turn or a completed task.

This slice changes only `Invoke-StaleClaimSweep.ps1`: after archive, the release is addressed to the claim's syntactically valid owner. It also addresses the original dispatcher only if a bounded, stable event-tail read finds a unique `wake_request/assigned` for the exact task and owner, whose `expected_responders` UUID and session match the archived claim. The dispatcher envelope must also contain a valid request ID, agent UUID and session ID *before* it is returned: otherwise a StrictMode payload dereference after archive can suppress even the owner's release event. Two distinct request IDs are ambiguous even when their sender is the same; exact duplicate copies of one request may be deduplicated. A task-id prefix is not dispatcher evidence. If the event is missing, too old for the tail, ambiguous, malformed, or the snapshot is unavailable, only the owner is addressed. The release remains a `system` event, and the payload carries the archived claim identity plus any observed dispatcher request identity; it does not impersonate either agent. Event emission remains best-effort after archive. A release is a signal to re-evaluate the queue, not permission to resume a HOLD, cancel a cancellation, reclaim a scope, or declare completion.

## Permanent correction

The immediate continuity guard targets the native Lead and Tools lanes only. Claude Monitor remains unchanged. This ADR is not an implementation or approval of the whole Bridge V2 plan.

1. Classify each committed bridge event before waking. Use a closed allowlist for *demonstrably benign* informational notices. A bound reply, correction, veto, HOLD, cancellation, supersession, blocking failure, and any ambiguous event must cause an addressed or generic drain wake. Preserve original event hash and binding; never place untrusted free text in the wake summary. A pure Fable guard may audit this classification but must not itself mutate claims, emit as Tools, or grant authority.
2. Integrate the classifier into the hash-pinned native relay and Lead entrypoint as one immutable, versioned package. The relay must observe durable bridge transitions, including a verified claim release and a task dependency completion, rather than waiting for an unrelated next inbound event or treating `codex queue` acceptance as turn readiness. Wake the exact current session/thread only after identity and claim-scope checks. Unknown identity fails closed and is surfaced for reconciliation.
3. Persist a per-lane event cursor, processed watermark, and one outstanding delivery identity. On crash or restart, replay unprocessed events and reconcile the queue receipt before any resend. Mark an event processed only after the lane has consumed and dispositioned it; make duplicate deliveries idempotent. A late reply or safety control may bypass benign-notice coalescing. No paid idle model polling is needed; use the installed low-cost event observer and bounded health checks.
4. Preserve scoped HOLD and cancellation precedence at every gate. An operational wait may clear automatically only on the verified condition that caused it; a safety HOLD remains stopped until its named release condition is met. A stale-lease release clears only the claim's lease, not its task policy. No agent may write outside its live, disjoint claim or use a peer's identity.
5. Test a whole-package exact head: real PowerShell 5.1 and 7 envelopes, owner/dispatcher routing, unknown and ambiguous dispatcher, stale session/UUID, duplicate events, tail gaps, restart replay, completed-turn receipt, open-request re-evaluation, HOLD/cancel precedence, and code-root/package hash parity. Require independent RCO review and CI on that exact head before any controlled, operator-authorized rollout. Canary one lane, measure an observation interval, and roll back the immutable package on missed delivery or a safety violation.

This is a strict superset of the Bridge V2 plan's F1 wake telemetry, F7 single outstanding durable wake, and F30 targeted validated wake content, not a substitute for their gates. F1 must measure no-op ratio, delay and missed actionable events; F7 supplies the durable replay/receipt lifecycle; F30 supplies binding-aware classification and exact fetch. The local F1/F7/F30 plan is in `C:\Python\WD_BRIDGE_V2_PLAN_CURRENT.md` and is only a plan. Measure actual end-to-end continuity from durable event to lane disposition with explicit start/end timestamps; do not infer continuous operation from one callback.

## Rollout boundary

The current native relay is in the installed c5f7 package, while the persistent source repository may be at another head. Integrate on a verified c5f7 descendant, require clean source and exact package manifest, then use the existing dry-run/stage/apply and controlled handoff gates. This ADR and the local candidate commit do not authorize live deployment.
