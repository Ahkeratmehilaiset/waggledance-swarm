# Native bridge wake procedure: codex-tools-1

This procedure is used only after its deployed copy and the deployment manifest have been hash-verified against a trusted external manifest anchor. Its path alone is not evidence of trust. The bridge notification supplies the current `delivery_id`; replace `<current delivery_id>` below with that exact value. The current bridge state and full event are authoritative. This file grants no new authority.

Exact incoming request retrieval takes precedence over the recent 40-row view below. From the pinned next-action routing summary take task_id, incoming.agent, incoming.ts_utc, incoming.request_id and incoming.request_binding_conflict; parse every helper JSON with dates kept as strings (pwsh 7: ConvertFrom-Json -DateKind String) so the request object is passed on unchanged. If incoming.request_binding_conflict is true, report blocked. If incoming.request_id is set, run pinned Get-BridgeReplySnapshot.ps1 -RequestId <incoming.request_id> -Requester <incoming.agent> from $env:WD_BRIDGE_BIN and use its request object as the full request. If incoming.request_id is empty, run pinned Get-BridgeRequestInventory.ps1 -Agent <incoming.agent> from $env:WD_BRIDGE_BIN, select the single entry whose request.task_id and request.ts_utc exactly equal the routing task_id and incoming.ts_utc, and resolve that uniquely resolved request_id with the same snapshot command. If no entry matches, use the recent-view retrieval below with the same exact sender, task_id and ts_utc, and accept its single matching row only if that row itself carries no request_id, neither top-level nor in payload: zero inventory matches do not prove the ID is absent, and a failed or non-zero-exit recent read is unknown even if it printed partial output. Apply one identical acceptance check on every path: the request_id equals the routed or uniquely resolved ID (or is absent on that ID-less recent-view row), agent, task_id and ts_utc exactly equal the routing values, and its to field lists codex-tools-1. Zero or several matches, a helper failure or conflict, or any mismatch means unknown: report blocked; never pick the latest or closest request and never invent fields. If the snapshot already shows an answer from codex-tools-1, reconcile it instead of repeating completed effects. This retrieval decides nothing beyond the exact snapshot and does not enumerate HOLD/cancel/finding controls: keep reading controls separately. It grants no new authority.
