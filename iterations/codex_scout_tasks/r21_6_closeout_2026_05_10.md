## What this PR ships

Final R21 closeout. Operator decision 3 ("Docker registry: GHCR
primary, no Docker Hub yet, public visibility OK") is implemented as
a GitHub Actions workflow rather than a local Docker build because
**Docker Desktop is unable to start on the build machine**:

```

> docker info
Error response from daemon: Docker Desktop is unable to start
```

Mounting the local image-build directly into this PR's evidence
stream is therefore not possible. Instead, R21.6 ships:

1. **`.github/workflows/release-docker.yml`** — `workflow_dispatch`
   + `release.published` triggered build/push to GHCR. Builds the
   canonical tag, the sliding alias, and the Profile S/M aliases per
   operator decision 3. Refuses to publish if the tag does not end in
   `alpha` (operator decision 2 hard guard against accidental stable
   promotion). Smoke test job pulls the image, asserts Profile S
   `BridgeLLMClient.disabled()` works, and asserts the redactor scrubs
   `alice@example.org`. **Skips updating `waggledance:latest`** per
   operator.

2. **This document** — operator-runnable post-merge checklist for the
   parts that can't be wired into the workflow (the actual `git tag`,
   the `git push --tags`, the GitHub release creation).

```powershell
# 3. Create the GitHub release as PRERELEASE
gh release create $TAG `
  --title "$TAG" `
  --notes-file iterations/codex_scout_tasks/r21_6_release_notes_2026_05_10.md `
  --prerelease

# 4. Trigger the GHCR workflow (creates ghcr.io/.../waggledance:* images)
#    NOTE: the `release.published` trigger fires automatically when
#    step 3 completes, so step 4 is usually a no-op confirmation.
gh workflow run release-docker.yml `
  -f tag=$TAG `
  -f promote_alias=axis-b-alpha `
  -f profile_aliases=yes
```
